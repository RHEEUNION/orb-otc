기준일 2026-09-21. 테스트넷(Orbinum chain 2700) 기준으로 실제 검증한 내용만 "완료"로 적었고, 검증하지 못한 부분은 그렇게 표시했습니다.

## 2. 구현 완료

### 컨트랙트
| 기능 | 내용 |
|---|---|
| 에스크로 오더북 | 네이티브 ORB와 화이트리스트 ERC-20을 교환. 판매·구매 주문, 부분 체결, 언제나 가능한 취소 |
| 수수료 | 체결 금액(quote 토큰) 기준. 테이커는 가격에 더해 지불, 메이커는 가격에서 차감. 메이커율은 주문 시점에 고정. 수수료는 컨트랙트에 토큰별로 누적되고 `claimFees(token)`으로 수령 주소에 전송(수령 주소가 블랙리스트에 걸려도 거래가 막히지 않게 하려는 구조) |
| 다중 quote 토큰 | `setQuoteToken`으로 토큰 추가·비활성화. 비활성화해도 기존 주문은 체결·취소 가능. 6자리·18자리 토큰, USDT식(반환값 없음) 토큰 지원, 수수료를 떼는 토큰은 거절 |
| 비공개 수령 (Sell 주문) | 테이커가 체결할 때 ORB를 공개 주소 대신 Orbinum ShieldedPool precompile(`0x…0801`)로 자기 프라이버시 주소의 shielded note에 받음. shield가 실패하면 체결 전체가 되돌아감 |
| 운영 통제 | `pause`, 주소 blocklist(추가·삭제, 일괄), 소유권 이전. **취소는 어떤 경우에도 막지 못하고 관리자는 사용자 자금을 옮기거나 묶을 수 없음** |

## 4. 지금 안 되는 것, 그리고 이유

| 안 되는 것 | 이유 | 풀리는 조건 |
|---|---|---|
| Buy 주문에서 메이커가 ORB를 비공개로 받기 | ORB를 받는 쪽의 프라이버시 주소를 주문에 미리 넣어야 하는데, 그러면 EVM 주소와 프라이버시 주소의 연결이 온체인에 공개됨 | 주문마다 새 프라이버시 주소를 쓸 수 있는 방법(Hub 지원) 또는 다른 설계 |
| 스테이블(tUSD, 메인넷의 USDT/USDC) 쪽 비공개 | ERC-20은 shielded pool에 넣을 수 없음(등록·검증된 자산만, 그리고 EVM precompile이 ERC-20 shield를 지원하는지 미확인) | Orbinum이 해당 자산을 pool에 등록하고 EVM 경로를 제공 |
| 가격, 수량, 거래 주소 숨기기 | 컨트랙트 호출은 공개. 숨기는 것은 "shield 이후 ORB의 소유자"뿐 | 구조적으로 불가(일회용 주소로 신원 연결만 끊음) |
| 다른 네트워크의 스테이블로 바로 결제, 판매 대금을 다른 네트워크로 받기 | Orbinum에는 토큰 브릿지가 없음. 노드에 있는 것은 메시지 전달용 ISMP 팔레트뿐 | 메인넷 스테이블 경로와 브릿지 확정 |
| Tron | MetaMask로 서명 불가, 주소 형식이 다름, Hyperbridge 지원 목록에도 없음 | 별도 지갑 연동 |
| shielded ↔ shielded 원자적 스왑 | 에스크로 컨트랙트가 note를 다룰 수 없음 | ZK 기반 주문 매칭(별도 개발) |
| 받은 note가 Hub에 자동으로 뜨기 | Hub는 자동 스캔을 하지 않고 사용자가 Recover Notes를 눌러야 함 | Hub 쪽 변경 또는 안내 강화 |
| 주문 이력, 체결 내역, 차트 | 이벤트를 저장·표시하지 않음 | 4장 참고 |
| 자동 제재 스크리닝, KYC | 외부 서비스 연동이 필요하고 테스트넷에서는 검증 불가 | 6장 참고 |

### 알려진 위험과 제약
- 관리자 키가 **한 개**(배포 지갑)이고 로컬 `.env`에만 있음.
- 오더북을 8초마다 **전체 주문을 읽어** 표시함. 주문이 수천 건이 되면 느려짐.
- 비공개 수령의 가스는 **고정값 1,500,000**으로 지정함(precompile 호출은 가스 추정이 불안정했음). 메인넷에서 재확인 필요.
- 노트의 circuit version을 **상수 1**로 씀(테스트넷 활성 버전이 1이라서). 메인넷에서 값이 달라지면 note를 쓸 수 없게 될 수 있음. Hub는 체인에서 활성 버전을 읽어 씀.
- 프라이버시 주소 형식(`orbpriv3`)은 **공식 문서가 없어서 Hub 코드와 체크섬으로 역으로 확인**한 것임.
- USDT/USDC는 발행사가 컨트랙트 잔액을 **동결**할 수 있음(에스크로 컨트랙트가 오염된 자금을 받은 경우 등).
- 시연 사이트는 GitHub Pages라 캐시 헤더와 보안 헤더를 제어할 수 없음.
- 직접 EOA에서 precompile을 호출했을 때 한 번 원인 불명의 revert가 있었음(컨트랙트 경유 경로는 영향 없음).

## 6. 메인넷 오픈 전에 추가해야 할 기능

### P0 — 출시 차단 항목
1. **스마트컨트랙트 보안 감사** (외부 감사와 버그바운티). 현재 컨트랙트는 미감사.
2. **키 관리**: 멀티시그와 타임락, 배포·관리·수수료 수령 키 분리, 하드웨어 지갑. 테스트넷 키(로컬 `.env`)를 메인넷에 절대 재사용하지 않음.
3. **법률 검토**: 사업 관할, 라이선스·등록 필요 여부, 이용 약관(금지 행위), 개인정보 처리방침, 신고 채널. 상세는 `docs/COMPLIANCE.md`.
4. **제재 스크리닝**: 외부 스크리닝 오라클을 컨트랙트와 프런트에서 확인. 일회용 주소 모델과 스크리닝이 서로 충돌하므로 정책 결정 필요.
5. **메인넷 스테이블 확정**: USDT/USDC 주소, 자릿수, 프록시·블랙리스트 특성 검토. 발행사 동결 시 대응 절차.
6. **모니터링과 알림**: 컨트랙트 이벤트(pause, blocklist, 대량 주문, 수수료 수령), RPC 장애, 프런트 오류 감시. 운영 런북(정지·복구 절차).
7. **주문 조회 확장성**: 전체 스캔 대신 컨트랙트 이벤트(`eth_getLogs`)로 조회하거나 오픈 주문 색인을 둠. Orbinum 인덱서는 필요하지 않음.
8. **실지갑 QA**: MetaMask, 모바일 지갑, 다른 브라우저, 메인넷 소액 리허설.

### P1 — 출시 직후 또는 함께
- 체결 내역과 가격 차트(이벤트 기반), 내 거래 이력
- 주문 만료, 최소 체결 수량, 전량 체결 전용(fill-or-kill) 주문
- 지정 상대 전용 주문(협의 거래에 필요한 OTC 특화 기능)
- Buy 주문의 비공개 수령
- 자동화 UI 테스트(Playwright 등), 접근성 점검
- 브릿지 경로 안내와 판매자 수령 네트워크 지정(`docs/CROSSCHAIN.md`)

### P2 — 이후
- 인텐트 기반 한 번에 크로스체인 체결, Tron, API, 대시보드

## 7. Orbinum 팀원이라면 미리 확인·협조받을 수 있는 것

| 요청 | 이유 |
|---|---|
| `orbpriv3` 프라이버시 주소와 note memo 형식의 공식 명세 | 지금은 역으로 확인한 것 |
| 메인넷의 view tag 활성 leaf 값과 활성 circuit version | note 생성 규칙이 바뀔 수 있음 |
| `protocol-core`(WASM) 최신 버전 게시, 또는 dapp용 note 생성 라이브러리 | 현재는 SDK 의존성으로 직접 구현 |
| EVM precompile로 ERC-20(USDT/USDC) shield가 가능한지, 자산 등록 계획 | 스테이블 쪽 비공개 가능 여부 |
| precompile 호출의 가스 특성과 메인넷 가스 정책 | 고정 가스값 확정 |
| 메인넷 USDT/USDC 컨트랙트 주소와 브릿지 경로(Hyperbridge 인텐트 지원 여부, 일정) | 정산 자산과 크로스체인 설계 |
| Hub의 "Recover Notes" 자동화 또는 dapp에서 note 수령을 알리는 방법(payment slip 전달 등) | 사용자가 수동으로 스캔해야 하는 문제 |
| 인덱서 API의 외부 앱 접근 허용(허용 도메인 등록, 봇 검증 예외, 호출 한도) | **필수는 아님.** 거래 이력은 우리 컨트랙트 이벤트를 RPC로 읽으면 되므로 인덱서가 필요 없음. note를 찾는 기능(예: 체결 후 note가 풀에 반영됐는지 자동 확인)을 만들 때만 필요 |
| 메인넷 RPC의 용량과 다중 엔드포인트 | 오더북 폴링 부하 |
| 멀티시그 컨트랙트 사용 가능 여부(Orbinum 위) | 관리자 키 구조 |
| 탐색기의 컨트랙트 소스 검증과 주소 라벨 | 사용자 신뢰 |
| 지갑·chainlist 메타데이터 등록 | 네트워크 자동 추가의 신뢰도 |
| 브랜드 사용의 서면 확인 | 로고 효과와 문구 |

## 8. 권장 순서

1. **지금부터 (팀 확인 없이 가능)**: UI 자동화 테스트, 이벤트 기반 조회 설계, 이력 화면, 만료·최소수량·지정 상대 주문 설계, 약관 초안, 모니터링 설계.
2. **팀 협조가 필요한 확인**: 7장의 요청 항목(특히 스테이블 주소, 프라이버시 주소 명세, circuit version).
3. **메인넷 후보 환경(있다면)에서 리허설**: 소액으로 전체 흐름, 가스 실측.
4. **출시 전**: 감사 완료, 멀티시그로 소유권 이전, 법률 검토 승인, 모니터링 가동, 데모와 별개의 정식 호스팅.
5. **출시 후**: 크로스체인, 스테이블 쪽 프라이버시 개선.

## 9. 용어 설명

**circuit version (회로 버전)**
Orbinum의 비공개 거래(Shield, Private Transfer, Unshield)는 영지식 증명으로 검증됩니다. 증명을 확인하는 "검증 키"가 회로 버전별로 온체인에 등록되어 있고, 체인이 회로를 업그레이드하면 버전이 올라갑니다. note는 자신이 어느 회로 버전으로 증명·지출돼야 하는지를 note 안(암호화된 메모)에 담고 있습니다. 그래서 note를 만들 때 버전을 정확히 적어야 나중에 지출할 때 맞는 회로로 증명할 수 있습니다.
지금 상수 `1`을 쓰는 이유: 테스트넷의 활성 버전이 1이고 지원 버전도 `[1]`뿐이기 때문입니다(체인에서 직접 조회해 확인함). 브라우저에서 활성 버전을 조회하려면 Substrate RPC 연결이 필요해서 무거운 라이브러리가 들어가므로 상수로 단순화했습니다. 메인넷의 활성 버전이 다르면 잘못된 버전이 적힌 note는 지출 시 문제가 생길 수 있어서, 메인넷 전에 **체인에서 읽어오도록 바꿔야** 합니다(Hub는 이미 그렇게 함). Hub에서 note가 보이는 것(스캔)에는 영향이 없습니다.

**인덱서와 "dapp 사용 허용"**
Orbinum 인덱서(`indexer.testnet.orbinum.io`)는 Hub가 note를 찾을 때 쓰는 서버로, 풀에 들어온 모든 commitment와 암호화된 메모를 순서대로 내려줍니다. 지금은 이 서버가 Cloudflare 봇 검증 뒤에 있어서 Hub 화면 밖의 프로그램(예: 제 스크립트)이 호출하면 차단됩니다. 다른 도메인의 웹사이트(우리 OTC)가 브라우저에서 호출하는 것도 허용 도메인(CORS)에 등록되지 않았다면 막힐 수 있습니다.
"dapp 사용 허용"은 Orbinum 팀이 외부 앱(우리 도메인)이 이 API를 쓸 수 있게 허용 도메인 등록, 봇 검증 예외, 호출 한도를 정해 달라는 요청입니다. 우리에게 필수는 아닙니다(거래 이력은 RPC로 읽을 수 있음).

## 10. 반드시 알아둘 것

- 테스트넷 관리자 키는 **이 개발 폴더의 `.env`에만** 있습니다(git에는 없음). 이 폴더가 사라지면 현재 테스트넷 컨트랙트의 관리 권한을 되찾을 수 없습니다. 테스트넷이라 치명적이지는 않지만, 메인넷에서는 처음부터 멀티시그와 하드웨어 지갑을 씁니다.
- 일회용 테스트 지갑 키(`spike/burner.json`)도 로컬에만 있으며 테스트넷 전용입니다.
- 소스 저장소는 private이고, 공개된 것은 빌드 결과물뿐입니다.
